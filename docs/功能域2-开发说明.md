# 功能域 2：订单与车辆开发说明

本文面向继续开发订单车辆域的同学，描述当前实际实现。接口细节以 [docs/apis/ride.md](./apis/ride.md) 为准。

## 当前范围

订单车辆域负责：

- 乘客发布拼车订单、搜索订单、加入拼单、查看订单详情。
- 车主查看可接订单、选择已认证车辆接单、完成订单。
- 乘客、车主和管理员取消订单。
- 车主新增车辆并一次性提交车辆认证资料。
- 管理员审核车辆认证申请。

车主身份认证属于账号域；只有车主身份通过后，用户才可以新增车辆并提交车辆认证。

## 页面与路由

### 乘客

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/passenger/home` | 乘客首页 | 入口导航和简要信息 |
| `/passenger/orders/publish` | 发布订单 | 填写路线、时间、人数、价格和偏好标签 |
| `/passenger/orders/search` | 搜索订单 | 查询可拼订单 |
| `/passenger/orders/mine` | 我的订单 | 查看当前乘客相关订单 |
| `/passenger/orders/:id` | 订单详情 | 查看详情、加入拼单、取消、进入聊天或用户资料 |
| `/passenger/chat/:orderId` | 订单聊天 | 与订单相关用户聊天 |
| `/passenger/feedback` | 提交投诉 | 表单名称仍沿用反馈组件，但产品语义为投诉 |

### 车主

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/driver/home` | 车主首页 | 接单入口、车辆认证入口、行程概览 |

| `/driver/orders/mine` | 我的行程 | 查看已接订单，完成或取消 |

| `/driver/chat/:orderId` | 订单聊天 | 与订单相关用户聊天 |
| `/driver/wallet` | 钱包 | 查询余额、提现和流水 |
| `/driver/feedback` | 提交投诉 | 投诉其他用户 |

### 车辆

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/me/vehicles` | 我的车辆 | 查看车辆认证状态；待审核申请只提供“撤回申请” |
| `/me/vehicles/create` | 新增车辆并提交认证 | 一次性填写车辆信息和认证资料 |

历史路由 `/driver/vehicles/*` 和 `/owner/vehicles/*` 统一重定向到 `/me/vehicles` 或 `/me/vehicles/create`。

### 管理员

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/admin/orders` | 订单管理 | 查看订单，前端隐藏已取消订单 |
| `/admin/vehicle-verifications` | 车辆认证审核 | 审核车主提交的车辆认证申请 |

管理员不显示普通用户个人中心。

## 订单状态规则

```text
published -> full
published/full -> locked -> completed
published/full/locked -> cancelled
```

| 状态 | 说明 |
| --- | --- |
| `published` | 招募中，可搜索、可加入、可接单 |
| `full` | 拼单人数已满，可接单 |
| `locked` | 车主已接单 |
| `completed` | 行程完成 |
| `cancelled` | 已取消，后端保留，前端不展示 |

当前前端在 `frontend/src/api/ride.js` 统一过滤 `cancelled` 订单：

- 乘客订单列表不展示。
- 车主订单列表不展示。
- 管理员订单列表不展示。
- 详情接口若拿到已取消订单，前端按不可见订单处理。

## 车辆认证规则

当前产品主流程：

1. 用户在个人中心提交车主身份认证。
2. 车主身份通过后，进入“我的车辆”。
3. 新增车辆时填写车辆基本信息和认证资料。
4. 前端先调用 `POST /api/vehicles` 创建车辆，再调用 `POST /api/vehicles/{vehicle_id}/verify-request` 提交认证资料。
5. 审核前用户只可以撤回申请。
6. 管理员在 `/admin/vehicle-verifications` 审核通过或驳回。
7. 车辆通过后才能用于车主接单。

用户侧不再提供：

- 补交资料。
- 编辑车辆。
- 停用车辆。
- 删除车辆。

后端仍保留这些接口作为兼容或后续扩展能力，但当前页面不暴露。

## Header 与身份传递

订单车辆域使用 Header 传递当前登录身份：

```text
X-User-Id: 3
X-User-Role: admin
X-Owner-Verified: true
```

说明：

- 数据库模式下 `X-User-Id` 必传。
- Mock 模式下缺少 `X-User-Id` 时，后端才会使用内置默认用户。
- 车主车辆管理和接单必须传 `X-Owner-Verified: true`。
- 管理员车辆审核必须传 `X-User-Role: admin`。

## Mock 与数据库模式

配置位于 `backend/.env`：

```env
RIDE_USE_MOCK=true
```

| 值 | 行为 |
| --- | --- |
| `true` | 使用 `backend/ride/ride_domain.py` 内置内存数据 |
| `false` | 使用 `ride_db` MySQL 数据 |

数据库模式不会自动混入 Mock 数据。如果需要演示数据，需要手动导入：

```powershell
mysql -u root -p ride_db < sql/ride/002_seed.sql
```

`002_seed.sql` 是可选演示种子。正式数据库或不希望出现演示订单时，不要导入该脚本。

当前演示账号 ID 与账号域 Mock 数据、`sql/account/002_seed.sql` 对齐：

| 用户 ID | 用户名 | 说明 |
| --- | --- | --- |
| `3` | `111` | 乘客 |
| `2` | `yxx` | 乘客，且车主身份已通过 |
| `998` | `driver1` | 车主身份已通过 |

## 与其他领域的对接

### 账号域

- 登录后前端从账号域返回结果中获取 `userId`、`role`、`driver.status`。
- 订单详情和聊天通过 `GET /api/users/profile/{user_id}` 把用户 ID 转换为注册用户名展示。
- 车主身份申请走 `POST /api/users/driver/apply/{user_id}`。

### 交易运营域

- 支付成功后可调用订单完成或后续回调逻辑。
- 聊天使用 `POST /api/chat/messages`、`GET /api/chat/messages`。
- 投诉从订单详情或用户资料进入，走 `POST /api/complaints`。

## 开发注意事项

- 新功能不要直接在页面里显示用户编号，优先通过账号域资料接口显示用户名。
- 新功能不要把数据库模式和 Mock 数据混用。Mock 只在对应 `*_USE_MOCK=true` 时使用。
- 新增订单列表入口时记得过滤 `cancelled`，或复用 `frontend/src/api/ride.js` 的封装。
- 新增需要返回上一页的详情/表单页时，在 `frontend/src/router/index.js` 的路由 `meta` 中配置 `backTo`，全局布局会自动显示左上角返回箭头。
- 车辆认证主流程以“一次提交、等待审核、审核前可撤回”为准。
