# 快速开发指南

本项目采用前后端分离与三域微服务结构。前端只访问网关 8000，网关再按路径转发到账号域、订单车辆域和交易运营域。

## 首次拉取

### 后端

```powershell
cd backend
pip install -r requirements.txt
.\scripts\bootstrap_env.ps1
.\scripts\run_services.ps1
```

`bootstrap_env.ps1` 会在存在 `.env.example` 时复制生成 `backend/.env`；如果文件已经存在会跳过。请按本机 MySQL 情况修改 `.env` 中的数据库连接和 mock 开关。

### 前端

```powershell
cd frontend
npm install
npm run dev
```

前端开发服务器运行在 5173，`vite.config.js` 会把 `/api` 代理到网关。默认本地网关为 `http://127.0.0.1:8000`。

如需改代理目标，可在 `frontend/.env` 中配置：

```env
VITE_USE_LEADER_API=false
VITE_API_TARGET_LOCAL=http://127.0.0.1:8000
VITE_API_TARGET_LEADER=http://<集成环境主机>:8000
```

## 端口约定

| 服务 | 端口 | 入口模块 |
|------|------|----------|
| 账号域 | 8001 | `backend.account.account_domain:app` |
| 订单车辆域 | 8002 | `backend.ride.service:app` |
| 交易运营域 | 8003 | `backend.ops.service:app` |
| 网关 | 8000 | `backend.gateway.main:app` |
| 前端 | 5173 | Vite |

前端永远不要直连 8001/8002/8003。

## 功能域分工

### 账号域

- 代码：`backend/account/*`
- SQL：`sql/account/*`
- 文档：`docs/apis/account.md`
- 主要能力：注册、登录、管理员登录、个人资料、车主身份认证、用户状态、信誉分。

### 订单车辆域

- 代码：`backend/ride/*`
- SQL：`sql/ride/*`
- 文档：`docs/apis/ride.md`
- 主要能力：订单发布/搜索/加入/接单/完成/取消、车辆管理、车辆认证申请与审核。

### 交易运营域

- 代码：`backend/ops/*`
- SQL：`sql/ops/*`
- 文档：`docs/apis/ops.md`
- 主要能力：支付、钱包、提现、聊天、投诉、管理员运营处理。

### 网关与公共配置

- 代码：`backend/gateway/*`、`backend/common/*`
- 主要能力：统一 `/api` 转发、读取服务地址、数据库参数和 mock 开关。

## Mock 与数据库模式

在 `backend/.env` 中独立切换：

```env
ACCOUNT_USE_MOCK=true
RIDE_USE_MOCK=false
OPS_USE_MOCK=true
```

- `true`：使用服务内存或固定 mock 数据。
- `false`：使用对应 MySQL 数据库。
- 数据库模式不会自动使用 mock 数据兜底。缺少真实登录用户时，订单车辆域写操作会返回缺少 `X-User-Id`。
- `sql/ride/002_seed.sql` 是可选演示数据。只想看真实业务数据时，仅执行 `sql/ride/001_init.sql` 建表，不导入 seed。

## 数据库初始化

按域执行建表脚本：

```powershell
mysql -u root -p < sql/account/001_init.sql
mysql -u root -p < sql/ride/001_init.sql
mysql -u root -p < sql/ops/001_init.sql
```

可选导入演示数据：

```powershell
mysql -u root -p account_db < sql/account/002_seed.sql
mysql -u root -p ride_db < sql/ride/002_seed.sql
mysql -u root -p ops_db < sql/ops/002_seed.sql
```

## 重要产品规则

- 注册页与登录页统一蓝色风格。
- 顶部导航栏在二级页面通过路由 `meta.backTo` 显示返回箭头。
- 已取消订单不在乘客、车主、管理员前端列表中展示；旧链接直达取消订单详情时按“订单不存在”处理。
- 用户展示优先显示账号域用户名，ID 仅用于路由、权限和后端字段。
- 投诉入口收敛到用户资料页：从订单详情点击具体用户，再投诉该用户。
- 管理员没有普通用户个人中心。
- 车辆认证申请提交后等待管理员审核，审核中仅支持撤回申请。
